Axcíon Systems building · Learning note 01

Lesson 1 · EmailOS development

Know which lifecycle owns the next move.

EmailOS crosses several lifecycles. They are not interchangeable commands: one routes an idea, one defines the system, one creates the project, one develops the operating capability, and one may build an AI artifact inside it. Your skill is choosing the owner.

10 minutes One-page lesson Win: lead the route to MVP testing Open the run card
Commands are owners, not a checklist: route → define → create the project → develop and prove the capability. An artifact branch returns to the capability that requested it.

3

Develop · /work-loop owns the capability

Can EmailOS repeatedly produce the approved result across its real seam?

Open the new EmailOS project and run /work-loop. It loads the capability-development method—there is no live /develop-capability command. Tell it to consume the approved 01–06 package and Stage 5 evidence as current reality rather than redo proven work.

/work-loop "Develop EmailOS as an operating capability: approved CRM record → reviewable draft → founder approval → Gmail action → reply, permission and next action preserved. Treat Systems Builder 01–06 and /new-project Stage 5 results as settled evidence; build only unproven slices."

CRM/Gmail integration, confidential data and sent communications signal consequential work: expect a synthetic trial, explicit approval, vertical slices, and failure/recovery behaviour. Method source

4

Release · stop after /work-loop Prove

Is the MVP ready to enter a controlled real-contact pilot?

Build one complete behaviour per slice. In Prove, test the operating seam with synthetic or redacted data: CRM authority, draft quality, approval enforcement, Gmail/CRM state, suppression, replies, visible failure and recovery. Existing Stage 5 evidence may satisfy a criterion; record it rather than rebuilding it.

Frame → Shape/G1 → Build slices → Prove/G2 → STOP # The controlled live wave belongs to Land, after release approval.

Finish line: the capability passed Prove and the release gate. The next lesson begins with the 10–15-contact pilot and adopt/hold/reject decision. Process source

Side branch only: if a /work-loop slice genuinely requires a new skill, command, agent or prompt, hand that bounded artifact to /develop-ai-resource. Its disposition returns to the capability; it never owns EmailOS or decides adoption.
