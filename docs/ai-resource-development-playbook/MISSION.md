# Mission: Develop and repair Axcíon AI resources deliberately

## Why
Patrik needs a repeatable way to turn rough notes into a well-routed, well-planned, implemented and verified capability or AI-resource change without having to remember the repository's many overlapping commands. The learning goal is not command memorisation; it is being able to recognize which lifecycle owns the need and why.

## Success looks like
- Given a page of rough notes, choose the correct first command without guessing.
- Distinguish an operating capability from the AI artifact that may support it.
- Know when to qualify, plan, implement, review, adopt, defer or stop.
- Use the repository's current review policy without stacking redundant review passes.
- Explain the reason for each major gate in plain language.

## Constraints
- The guide must work for a non-developer.
- It must describe the live repository as of 2026-07-30, including known transition points.
- It must use exact command names and point to the governing repository sources.
- The quick-reference page should be printable and usable during a real session.

## Out of scope
- Creating a new meta-command or skill to automate this playbook.
- Teaching the full `/prime` → `/session-start` → `/session-plan` session ritual.
- Explaining how to author every possible AI-resource type in detail.
- Replacing the lifecycle owners already present in the repository.
